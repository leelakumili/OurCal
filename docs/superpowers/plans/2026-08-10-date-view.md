# Date View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pick any date, past or future, and see that day's schedule — without changing how the existing 30/90/180/365-day range views behave.

**Architecture:** `/api/events` gains an optional `date=YYYY-MM-DD`. When present, the fetch window becomes local midnight → next local midnight in `TIMEZONE` instead of `now → now + days`, on both the Google path and the demo path. The client gains a native date input beside the range dropdown; setting it disables the dropdown, hides the stat tiles, and renders a single day under one heading.

**Tech Stack:** Python 3.9+ standard library only; vanilla JS embedded as a string in `ourcal.py`; `unittest`.

**Spec:** `docs/superpowers/specs/2026-08-10-date-view-design.md`

> **Corrected after implementation — Task 4 and 5 below are out of date on one

## Global Constraints

- **The entire application is one file, `ourcal.py`.** No new modules. The UI is an HTML/CSS/JS string inside it.
- **Standard library only.** No new dependencies, Python or JS.
- **`import time` at `ourcal.py:8` is the `time` module**, used at `ourcal.py:784` and `ourcal.py:2751`. Never write `from datetime import time` — it shadows the module and breaks the sign-in poller. Use `datetime.min.time()` instead.
- **Tests must never write to the real data directory.** In a checkout `data_dir()` is the repo root, which holds the maintainer's live `credentials.json` and `token_*.json`. `CONTRIBUTING.md:49` records a near-miss.
- **Tests run in demo mode** (`tests/test_ourcal.py:3` sets `OURCAL_DEMO=1` before importing). Any behaviour implemented only on the Google path is untested by construction.
- **Bad input degrades, it does not error.** `clamp_days` (`ourcal.py:572`) turns `"banana"` into the default rather than raising; `parse_view_date` mirrors that exactly.
- **Run the suite with** `python3 -m unittest discover -s tests -q` — bare `python3`, not `.ourcal-venv/bin/python` (it has no pytest and CI uses bare `python3`).
- Existing suite: **348 tests, 1 skipped.** Every task must leave it green.

```python
def parse_view_date(value):
    """A YYYY-MM-DD query value as a date, or None for anything else.

    None for absent, empty, malformed, or out-of-calendar input. Mirrors
    clamp_days: bad input degrades to the default view rather than erroring.
    The value always arrives from a native date input in practice, so a
    malformed one means a hand-crafted request, not a user mistake.
    """
    if not value:
        return None
    try:
        return datetime.strptime(str(value), "%Y-%m-%d").date()
    except (TypeError, ValueError):
        return None
```

`America/Los_Angeles` is the configured `TIMEZONE` default and observes DST. In 2026 it springs forward on **March 8** (23-hour day) and falls back on **November 1** (25-hour day).

**The UTC conversion below is load-bearing.** CPython short-circuits `b - a` to a *naive* subtraction when both operands share the same `tzinfo` instance, so subtracting the two bounds directly reports 24 hours on every date and the DST assertions would pass against any implementation.

```python
        ourcal._TZ = None                       # defeat the cache per test
        self.addCleanup(lambda: setattr(ourcal, "_TZ", None))

    def _span_hours(self, on_date):
        lo, hi = ourcal.day_window(on_date)
        a = datetime.datetime.fromisoformat(lo).astimezone(datetime.timezone.utc)
        b = datetime.datetime.fromisoformat(hi).astimezone(datetime.timezone.utc)
        return (b - a).total_seconds() / 3600

    def test_starts_at_local_midnight(self):
        lo, hi = ourcal.day_window(datetime.date(2026, 8, 19))
        self.assertTrue(lo.startswith("2026-08-19T00:00:00"), lo)
        self.assertTrue(hi.startswith("2026-08-20T00:00:00"), hi)

        # wall-clock and handles it. This pins the property so a later switch
        # to naive datetimes or a fixed offset fails loudly.
        self.assertEqual(self._span_hours(datetime.date(2026, 3, 8)), 23)

        self.assertTrue(lo.startswith("2025-02-03T00:00:00"), lo)
```

```python
def day_window(on_date):
    """(time_min, time_max) RFC3339 strings spanning on_date in TIMEZONE.

    Local midnight to the next local midnight, both built from tz()-aware
    datetimes so each carries the zone's real offset on its own date — which
    is what makes a spring-forward day 23 hours and a fall-back day 25.
    """
    midnight = datetime.min.time()
    start = datetime.combine(on_date, midnight, tzinfo=tz())
    end = datetime.combine(on_date + timedelta(days=1), midnight, tzinfo=tz())
    return _iso(start), _iso(end)
```

```python
def event_on_date(ev, on_date):
    """Does this normalized event overlap on_date, in TIMEZONE?

    Overlap rather than "starts on" — Google returns anything intersecting a
    timeMin/timeMax window, and the demo path has to match that or the two
    backends disagree about what a day contains. An 11pm-to-1am event belongs
    to both days it touches.
    """
    if ev.get("allDay"):
        # Google's all-day end is exclusive: 19th->20th is one day.
        try:
            start = datetime.strptime(str(ev.get("start"))[:10], "%Y-%m-%d").date()
            end = datetime.strptime(str(ev.get("end"))[:10], "%Y-%m-%d").date()
        except (TypeError, ValueError):
            return False
        return start <= on_date < end
    lo, hi = day_window(on_date)
    try:
        start = datetime.fromisoformat(str(ev.get("start")))
        end = datetime.fromisoformat(str(ev.get("end")))
    except (TypeError, ValueError):
        return False
    return start < datetime.fromisoformat(hi) and end > datetime.fromisoformat(lo)
```

```js
    const ordered=evs.slice().sort((a,b)=>String(a.start).localeCompare(String(b.start)));
    html+=`<div class="day">${esc(fmtDayHeading(DATA.date))}</div>`;
    for(const ev of ordered){ try{ html+=evRow(ev,ROWS.push(ev)-1); }catch(e){} }
  } else {
    const groups={}, keys=[];
    for(const ev of evs){ const k=dayKey(ev.start,ev.allDay); if(!groups[k]){groups[k]=[];keys.push(k);} groups[k].push(ev); }
    keys.sort();
    for(const k of keys){
      html+=`<div class="day">${esc(fmtDayHeading(k))}</div>`;
      for(const ev of groups[k]){ try{ html+=evRow(ev,ROWS.push(ev)-1); }catch(e){} }
    }
  }
  box.innerHTML=html;
```
